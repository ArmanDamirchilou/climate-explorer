# Climate Explorer version history

The dates below preserve the actual development history. A release number does not establish competition eligibility or change the 11 November start date.

| Version | Change and reason | Evidence and limits |
|---|---|---|
| 0.1 | Initial local NASA POWER tool, built 11 November. Selected locations, annual trends, monthly view and exports. | Original baseline hash is retained. The private baseline archive is excluded from publication because it contains a local path. This was an early prototype. |
| 0.2.0 | Added statistical sensitivity checks, fixed-window comparisons, synthetic evaluation, source comparison and replay. | A browser JSON round trip exposed a numeric hashing defect. Do not use the retained failed export as a successful replay example. |
| 0.2.1 | Normalized integral numeric values for stable source hashing across Python and browser JSON. | Actual Chrome export and replay passed. The change did not establish universal interval calibration. |
| 0.3.0 | Published the frozen demonstration, added the investigation worksheet and source diagnostic, strengthened engineering checks, and prepared the submission materials. | Public examples replayed. The seven-page PDF was checked and published. Science, engineering and submission agents documented independent AI reviews. |
| 0.4.0 | Added four fixed periods, a comparison of rates from the same source, opt-in saved notes, limited browser import verification, and a printable investigation. | Period choice, notes restore and the browser verification limits were checked in Chrome on 13 November. Printing was checked in Chrome. Published tag v0.4.0 and Linux checks preserve this milestone. |
| 1.0.0 | Packages the improved investigation workflow with a seven-page PDF, 29-second captioned video, Farhad handoff, review rubric and student practice guide. | The full workflow, media and handoff contract are documented. See RELEASE_NOTES.md, the exact tag and evaluation/RELEASE_VERIFICATION.md for final release evidence. |

Later release notes should explain what changed, why it matters, how it was checked, and the material limits. Keep earlier artifacts identifiable. A rebuilt PDF or video should retain its source hashes and review record so a reviewer can identify the data behind the displayed values.
